# English Version (Web + AI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The eRecept website works in English with a RU/EN switch (doctor pages, public prescription page, box check). It shows English medicine names, meal labels and AI answers, so the jury can use it and English screenshots and video can be made.

**Architecture:**
- New package `internal/i18n` holds the language from the request (`?lang=en` sets a `lang` cookie) and an EN dictionary keyed by the Russian source string, gettext-style. A missing key falls back to Russian.
- Templates call `{{t "…"}}`. The real `t` is bound per request on a clone of the parsed template.
- Medicines get `name_en` / `substance_en` columns. Box-check copy gets an EN variant. AI leaflet summaries get an EN translation stored next to the Russian one.

**Tech Stack:** Go, chi, html/template, pgx, anthropic-sdk-go v2 (`claude-opus-5-5`), embedded Postgres in tests.

**Spec:** in-chat request 2026-11-10: «давай делай анг яз и все на английском», approved «гооу». The mobile app is a separate plan.

## Global Constraints

- Russian stays the default. With no `lang`, every existing page renders exactly as before, and the existing tests stay green.
- The language comes from `?lang=en|ru`, which also sets cookie `lang` (1 year, Path=/), then from the cookie, then from the default `ru`.
- User-entered data (patient names, doctor names, comments) is never translated.
- Box-check safety rules are unchanged in EN: never "safe to take", and every non-match says "show the pharmacist".
- Paid AI: the EN summaries backfill is a one-time ~30 calls. Live checks are at most 2 paid calls.
- Commits carry only the user's name.

## Review Focus

- **A template string wrapped in `t` without an EN entry** renders Russian on an EN page. Test: every `{{t "…"}}` literal in templates/*.html has an EN entry.
- **Unknown `?lang=xx`** must fall back to ru and must not set the cookie.
- **A medicine typed in English in the doctor form** ("Glucophage") must link to the same catalog item as «Глюкофаж».
- **EN box check:** the substance check compares Russian substances internally, so English box text still matches.
- **Pages rendered by `renderFragment`/`renderPlain`** must get `t` too.

### Task 1: i18n core and language switch
**Files:**
- Create: `internal/i18n/i18n.go`, `internal/i18n/en.go`, `internal/i18n/i18n_test.go`
- Modify: `internal/web/web.go` (middleware, template funcs, render functions), `internal/web/templates/layout.html` (RU/EN toggle, `lang` attribute)

**Produces:**
- `type Lang string`; constants `RU`, `EN`
- `func FromContext(ctx) Lang`
- `func Middleware(next http.Handler) http.Handler`: reads `?lang` and the cookie, sets the cookie, and stores the language in the context
- `func T(l Lang, ru string) string`
- `func Tf(l Lang, ru string, args ...any) string`, which applies `fmt.Sprintf` to the translated format

**Tests:**
- `T(EN, "Рецепт") == "Prescription"`; `T(RU, x) == x`; an unknown key falls back to Russian.
- Middleware: `?lang=en` sets the cookie and makes the context EN; `?lang=xx` gives RU and no cookie.
- `TestTemplatesTranslated` (in web): regex `{{t "([^"]+)"}}` over templates must find an EN entry for every match.
