# Электронные рецепты с контролем приёма — дизайн

Источник: задание автора проекта (Бахтияр) от 2026-11-01. Ниже — его требования
(сохранены дословно по смыслу) и решения, принятые при планировании (помечены
«Решение Claude»).

## Зачем

Врачи пишут рецепты от руки, почерк непонятный; пациенты забывают пить лекарства
и не знают, где купить дешевле. Демо для хакатона: важнее, чтобы всё работало и
красиво показывалось, чем идеальная архитектура. Автор — Go-разработчик, работает
один: код простой, понятный, без лишних абстракций.

## Сценарий

1. Врач заполняет рецепт на веб-странице, система генерирует QR-код.
2. Пациент сканирует QR в мобильном приложении, оно само строит расписание приёма.
3. Приложение напоминает о лекарствах и воде, пациент нажимает «Выпил». Не отметил
   за 60 минут — уведомление родственнику.
4. Пациент находит лекарство в аптеках и сравнивает цены.
5. Врач видит, насколько пациент соблюдает лечение.

## Архитектура (решения автора)

- Бэкенд: Go 1.22+, chi, PostgreSQL + pgx, миграции простыми SQL-файлами,
  github.com/skip2/go-qrcode, bcrypt, Expo Push API обычным HTTP, фоновая горутина
  раз в минуту, конфиг через .env, docker-compose, часовой пояс Asia/Almaty.
- Страницы врача и аптеки: html/template + htmx, без React.
- Приложение пациента и родственника: React Native + Expo, TypeScript, expo-router,
  expo-camera, expo-notifications (локальные), AsyncStorage, expo-image-picker.
- Структура: cmd/app/main.go, internal/(db, models, api, web, notifier), mobile/.
- Интерфейс на русском.

## Роли

**Врач (веб).** Вход по логину/паролю. Рецепт: ФИО, дата рождения, лекарства
(название, дозировка, раз в день, дней, до/после/во время еды, время приёма),
комментарий. «Вода»: каждые N часов с–до. После сохранения — QR и «Распечатать
рецепт». Статистика: сколько приёмов отмечено и пропущено.

**Пациент (приложение).** Скан QR → загрузка рецепта. Локальные уведомления на весь
курс (лекарства и вода), работают без интернета. Кнопки в уведомлении «Выпил»,
«Через 15 мин». Отметки в AsyncStorage, отправляются на сервер при появлении сети.
Экраны: «Сегодня», «Курс» (процент), «Где купить», «Настройки» (пригласить
родственника). Фото таблетки — необязательно.

**Родственник (то же приложение).** Вход по коду-приглашению. Push при пропуске,
отправляет Go-сервер через Expo Push API.

**Аптека (веб).** Вход. Лекарства с ценой и наличием: вручную или CSV.

**Поиск.** У каждого лекарства «Где купить»: аптеки с наличием, сортировка по цене
или расстоянию, адрес, часы, «На карте». Аналоги (то же действующее вещество) — с
пометкой «Согласуйте замену с врачом или фармацевтом».

**Тестовые данные.** 2 врача, 8 аптек в одном городе, 30 лекарств с разными ценами.

## Дизайн (решения автора)

Спокойный медицинский стиль, без градиентов, теней, анимаций и эмодзи. Inter, текст
15px, заголовки 24px. Фон #F6F8FA, карточки #FFFFFF, рамка 1px #E5E7EB, скругление
12px. Текст #1F2937, второстепенный #5B6472. Акцент #0F766E только для главных кнопок
и активных элементов. Поля и кнопки ≥44px, скругление 8px. Главная кнопка — заливка
акцентом, белый текст; второстепенная — белая с серой рамкой. Веб: белая шапка 64px
с логотипом и меню; врач — слева форма (таблица лекарств, «+ Добавить лекарство»),
справа карточка с QR; адаптивно для телефона. Приложение: крупные кнопки (пожилые
пациенты). Напоминания короткие: название, доза, до/после еды, «день 3 из 7».

## Развёртывание (решено в разговоре 2026-11-01)

- Сервер на Render (https://erecept.onrender.com), Docker, бесплатный тариф, регион
  Frankfurt, автодеплой из github.com/bakhtiyararzimetov/erecept (main). База —
  бесплатный Postgres Render (истекает 2026-12-01).
- 750 бесплатных часов общие с другими сервисами аккаунта, поэтому самопинг только
  08:00–23:00 (KEEP_AWAKE_HOURS). Ночью сервер может спать.

## Решения Claude

- **Пациент без логина.** Приложение генерирует случайный `device_secret`, хранит в
  AsyncStorage и шлёт в заголовке `X-Device-Secret`. Сервер создаёт пациента при
  первом обращении. Родственник — так же, своим секретом.
- **QR содержит ссылку** `<PUBLIC_URL>/r/<code>`. Обычная камера телефона откроет
  читаемую веб-версию рецепта (удобно в аптеке), приложение берёт `code` из ссылки.
- **Привязка рецепта.** При сканировании (`claim`) первый день курса = день
  сканирования, приёмы на весь курс создаются в таблице `doses`. Повторное
  сканирование другим телефоном перепривязывает рецепт к нему (удобно на демо).
- **Пропуски.** Пропущен = не отмечен и прошло ≥60 мин. Push родственнику — только
  за приёмы, запланированные после привязки и не старше 3 часов (чтобы после ночного
  сна сервера не прилетела пачка старых уведомлений).
- **Вода** не хранится на сервере, приложение считает её само.
- **Лимит уведомлений iOS (64).** Приложение планирует ближайшие 60 уведомлений и
  перепланирует их при каждом открытии и после каждой отметки.
- **Фото таблетки** хранится в базе (`bytea`): диск бесплатного Render не постоянный.
- **Тестовые данные** загружаются автоматически при старте, если таблица врачей
  пуста (Render free не даёт консоль). Есть и ручной запуск `go run ./cmd/seed`.
- **Push родственнику** требует Expo push-токен, а он требует EAS projectId. Без
  `eas init` (нужен вход автора в Expo) приложение работает, но токен не получает —
  это описано в README.
- Аптеки в тестовых данных — вымышленные названия, реальные районы Алматы.
